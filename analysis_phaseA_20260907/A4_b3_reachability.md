## 1. 模拟模型（假设必读）

从 VALIDATION DEVELOPMENT 结构实测：每源 measured 候选数 m ∈ {2,3,4}（MRL≈3.0，MPRAU/HL/polyA=2.0）。33→实际 100% 源 ≤4。生成池按泊松/二项式发射真实 measured 候选，逐槽发射概率 `p_task` 由实测 support(32) 校准：
`p = 1−(1−support(32))^(1/32)`（overall→0.0086；按任务 MRL=0.0117, MPRAU=0.0018, HL=0.0017, polyA=0）。

两个指标分开建模（这是本分析最关键的建模判断）：
- **Model A — recovery@budget（B3 门指标 `candidate_recovery_rate`）**：统计真实 measured 序列出现在 32 池“任意位置”的比例，**与 critic 排序无关** → ρ 不影响它，只取决于生成器池覆盖。
  `recovery_source = min(hits, m)/m，hits~Binomial(B, p_task)`，宏观取 891 源平均。
- **Model B — hit@1 引导选择**（ρ 唯一起作用的量，TreeG k1 式）：
  `guided_hit@1 = ρ × support(B)`，ρ = critic 把“真最好 measured 候选”排到 top-1 的条件概率。

## 4. “0.35 需要哪一档 ρ？”

对 **hit@1** 指标（critic 可干预的唯一量）：`ρ_needed = 0.35 / support(B)`

| 池 B | support(≈) | ρ_needed 达 0.35 | 可行性 |
|---|---|---|---|
| 32 | 0.24 | **1.48** | 不可行（>1.0） |
| 64 | 0.41 | 0.86 | 可行 |
| 128 | 0.65 | 0.54 | 可行 |
| 256 | 0.78 | 0.44 | 可行 |

- **在现行 32 预算下：0.35 无法由任何 ρ 达到**（ρ 需 1.48）。
- 对 **recovery@budget**（B3 门指标）：**ρ 完全不参与**，0.35 需把池放大到 B≈120+（或提升生成器覆盖 p）。

## 5. support(32) vs support(256)（tail-existence 复核）

- support(32) ≈ **0.24**；同生成器下 support(256) ≈ **0.78**（A2 亦 ~0.89 估计）。→ **尾部真实候选可被更大采样密集采到**，尾部质量**存在**。
- 结论：B3 0.35 不可达的根因是**32 预算 + 生成器覆盖不足**（support 只 24%、recovery 上界 ~0.1–0.13），而非 critic 判别力；critic ρ 只在池内起作用，当前即便 ρ=1.0 也到不了 0.35。

## 6. amendment 建议（V6 立项输入）

1. **优先：扩池/加算量**。单独靠覆盖把 recovery@budget 拉到 0.35，池需 ~120+；建议直接放 256（预算 891×256），预计 recovery@budget≥0.6。这直接绕开 32 预算下的不可达。
2. **其次：改进生成器覆盖 p**（让引导式 SetFlow 主动把真实高频候选推向池内，而非仅在同源 32 池内重排）——A2 显示 guidance 当前对覆盖零贡献。
3. **critic 判别力 ρ 是三级杠杆**，仅在池变大后有效：B=256 时 ρ≈0.44 即可 hit@1 0.35，当前 V5 critic hit@1≈0.035（≈ρ≈0.14）落差大，可作为 V6 训练目标但非首要。
4. **指标口径修正**：recovery@budget 分母实为“该源 measured 数”（2–4），非 32；建议 V6 单独报告 support@B 与 per-measured recovery，避免“恢复比例”被小分母放大误导。
