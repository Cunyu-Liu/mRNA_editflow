> **状态：PREREGISTRATION（2026-09-10 晚，用户指示「负结果不代表放弃，从问题中反思继续解决」）**。触发：Phase C/D2 负结果的结构性反思——「覆盖×排序两目标冲突」发现 + B256 产物离线模拟显示 top-32 选择策略达 oracle 上界且全指标显著。

## 1. 反思链（为什么此前全负而这个方向有效）

1. **V5/V8/β/检索引导全部作用于转移速率**（BASE_TRANSITION_RATE × exp(β·ΔV)）——A2/B3 实测：对池覆盖零贡献。机制盲区：势能引导只能**重加权已访问状态**。
2. **扩池（B=256）提升覆盖但稀释排序**（topTieShare 0.82→0.62；MRL covered 源 top5 72%→59%）——单纯扩池是把两目标互相拖累。
3. **破局点：提交集合 ≠ 生成集合**。B2 判据只看提交的 32 个候选。**用大池探索（B=256 采样）、按 generation_score（log 频率，模型自身置信度）选回 top-32 提交**：
   - 保留 B=32 的排序结构（选回的都是高频=模型置信候选）
   - 叠加 B=256 的覆盖增益（support 0.242→0.292）
   - 离线核算（891 全量，配对 bootstrap）：Δsc-hit@1 **+0.034 CI [+0.021, +0.048]**（≥+0.03 过 B2 门）、Δsupport +0.049 排零、Δrecovery +0.043 排零
   - **已验证 = oracle 上界**（选择器在 generation_score 口径下已最优——A-gen 与 A-oracle 数字相同，说明 genscore 选回就是最优选择）

## 2. 方案定义（预注册）

```
提交集 = top-32(按 generation_score = log(empirical_count/total), 并列取任一) of B-shot 采样池
```

- **参数 B**（探索宽度）：主臂 B=256（已有产物直接核算）；扩展臂 B=512、B=1024（采样预算翻倍/四倍，探覆盖增益的边际曲线；运行 ~2×/~4× 采样时间）
- **种子匹配**：与 b_fix2 pass-2 seed20260915 同源（decoder_seed_base 沿用 runner 默认）
- **多 seed 稳健性**：B=256 主臂补 seed±1 两副本（判定门要求 3/3 seed 方向一致——防 calib100 假阳性教训重演）
