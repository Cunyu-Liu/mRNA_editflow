# 路线 A 必要性与确定性分析（D3 拍板前置，2026-09-03）

> 依据：用户批准 A+B 但要求"做路线 A 之前，再考虑一下必要性和确定性。因为不清楚用这么大量的数据集做微调会有什么后果"。本文档回应这一质询，作为路线 A 预注册的前置分析。诚实原则：风险不回避，不确定性如实标注。

## 1. 路线 A 是什么（精确表述）

**Step 1**：在 GSE114002 原生配套的 Sample 2019 280K 随机 5'UTR 文库上监督微调 mRNABERT（预测绝对 MRL）
**Step 2**：以 Step 1 权重为初始化，在本项目 MRL 任务（2,443 行 TRAIN，Δy source-relative 排序）上做 per-task LoRA/head-only 适配
**对照（路线 B）**：域内多任务微调（一套权重九任务，无外部库）

## 2. 必要性：路线 A 是当前最便宜的"判别性实验"

### 2.1 已排除的假说（全部有预注册数据）

| 假说 | 检验 | 结果 |
|---|---|---|
| loss 机制不够好 | V6 首训 + H3 λ 扫描 | **负**（0.0510/0.0883/0.0839 vs V5 0.1025，未过门）|
| 域内多任务先验不足 | W1' head/LoRA | **弱**（0.1336/0.1486 ≈ V5 基线）|
| 训练预算不足 | W0-continue | **负**（0.1800 回落，过拟合）|

### 2.2 剩余两个假说，路线 A 直接判别

MRL 差距（W0 天花板 0.1987 vs Optimus 0.3132，Δ=0.115）只剩两个可能来源：

- **H-prior（外部大库先验）**：Optimus 的赢法 = 280K 预训练 + 2,443 行 adapter。若先验是关键，mRNABERT + 280K + LoRA 应显著逼近 0.3132
- **H-arch（架构本身）**：0.5M CNN 的归纳偏置（局部 motif 卷积 + 池化）天然适配 MRL；170M 通用编码器不适配。若架构是关键，路线 A 后仍在 ~0.20 附近

**路线 A 是同时检验两者的最便宜判别器**：mRNABERT 基础设施、LoRA 迁移机制（W1' 已建好并测试）、280K 文库（原生配套、GEO 可得）全部现成。若不做，H-prior/H-arch 无法分离，W2（容量）方向也缺设计依据。

### 2.3 必要性的一个诚实让步

严格说路线 A **不是唯一判别器**。更便宜的两个对照实验（见 §4 Stage 0）可以先行提高确定性——这正是本分析建议的路径：**先用半天做 Stage 0 判别，再决定是否投入 280K 训练**。

## 3. 确定性：大库微调的具体后果与对策

### 3.1 后果一：数据泄漏（最严重，必须硬门处理）

**问题**：280K 文库**包含**本项目 VALIDATION/TEST 的源序列（3,899 条 GSE114002 记录全部来自同一文库）。直接在 280K 上预微调 = 在验证/测试结果上训练 → 任何"提升"都是污染假象，且摧毁 benchmark 的泄漏控制划分主张（R3，95% 近重复组件级划分）。

**对策（spec 已列为硬门，本分析具体化）**：
- Stage 0c：下载 280K 后，用现有近重复组件基础设施把所有与 VALIDATION/TEST 记录 95% 同源 的文库序列**全部剔除**（预计剔除 ~1-2K 条，保留 ~278K）
- 剔除清单 + 审计结果写入 benchmark leakage audit 表（Table 2 一行），无论正负
- 预注册声明：Step 1 数据 = 280K 减去 VAL/TEST 同源序列；TRAIN 同源序列保留（属 TRAIN 分布的合法扩增）

### 3.2 后果二：测量口径不匹配（H2 陷阱——本项目自己的假说）

**问题**：280K 训练的是**绝对 MRL 预测**（酵母无细胞体系、随机序列）；本项目任务是**源相对 Δy 排序**（人源内源 5'UTR、疾病变异、稀疏编辑）。本项目 H2 假说本身就是"绝对精度 ≠ 编辑优先级"——先验可能不迁移。

**对冲证据**：Optimus adapter（280K 先验 + 2,443 行任务微调）在 Δy 上拿到 0.3132 → 先验**经过任务微调后**可迁移（对 CNN 成立）。**未知的**：先验单独（不做任务微调）能迁移多少——这正是 Stage 0a 用 frozen-Optimus 直接测量的量。

### 3.3 后果三：灾难遗忘（多任务 critic 退化）

**问题**：在 280K 上全参微调 mRNABERT 会特化到 MRL；critic 的多任务能力（polyA 0.82 已达标）可能受损。

**对策**：**Step 1 用 LoRA（r=16）而非全参**——冻结主干 + 低秩适配，天然保留基础表征；全参臂作为消融（若时间允许）。Step 2 继承 W1' 禁全参条款。路线 B 作对照隔离"先验来源"。

### 3.4 后果四：论文措辞与公平性（坑 B 条款）

280K 阶段 = **supervised domain-library pre-finetuning**（监督迁移），论文不得写成 self-supervised pretraining；按协议 §三 条款 2 分列声明（外部模型原生预训练同等待遇，均不计入对位微调预算）。

### 3.5 后果五：算力/时间

280K × mRNABERT LoRA 微调 ≈ 数小时/epoch 量级（与 V5/V6 训练同量级）；本周内完成 Stage 0-2 可行（今天 Stage 0，明后天 Stage 1-2）。

### 3.6 确定性总评（诚实）

**中等偏上，非高**。支持面：Optimus 实证先验可迁移（经任务 FT）；mRNABERT 原文在 MRL 上有强结果；LoRA 小样本排序有文献。风险面：口径不匹配（H2）；0.962 的 mRNABERT 数字来自库内划分（无近重复控制），不可直接预期；先验对人源内源变异的域间隙。**预期管理：路线 A 是判别性假设检验，存在真实的负结果可能——负结果本身有科学价值（确认架构侧），但不应被预设为必赢。**

## 4. 分阶段 GO/NO-GO 设计（把不确定性变成便宜的决策点）

### Stage 0（半天，先做，全部现成资产）

| 步骤 | 内容 | 判别力 |
|---|---|---|
| 0a | **frozen-Optimus delta**：280K 预训练权重直接打分 source/candidate（不做任务 FT），在 GSE114002 VALIDATION 上算 Δy Spearman（harness 已有 Optimus 类，仿 Saluki frozen-delta 脚本）| 直接测"先验单独迁移量"。≥0.15 → 先验强迁移，路线 A 高信心 GO；≈0 → 看 0b |
| 0b | **Optimus-from-scratch 对照**：随机初始化 Optimus 架构在同样 2,443 行 TRAIN 上训练（0.5M 参数，分钟-小时级）| 分离架构 vs 先验。若 from-scratch ≈ 0.31 → 架构主导，路线 A 降级；若 ≈0.15 → 先验主导，GO |
| 0c | 280K 文库获取（本地下载→scp）+ 泄漏剔除审计 | 硬门，无论如何必须做 |

**决策规则（预注册）**：0a ≥0.15 **或**（0a <0.15 且 0b <0.20）→ 路线 A GO（Step 1 LoRA + Step 2 复用 W1' 机制）；0a <0.15 且 0b ≥0.25 → 架构主导信号，路线 A 降级为对照臂，W2 架构线优先；中间地带 → A+B 并行（已批准的形态）。

## 5. 结论

- **必要性：成立**——路线 A 是分离 H-prior/H-arch 的最便宜判别实验，且是 W 阶梯证据链指向的唯一未测路径；但应先做 Stage 0 的两个便宜对照把确定性买上去
- **确定性：中等偏上**——主要风险（泄漏/口径/遗忘）均有具体对策且入预注册；存在真实负结果可能，预期按假设检验管理
- **大库微调的后果**：五项（泄漏/口径/遗忘/措辞/算力）全部识别，两项（泄漏、措辞）是协议硬约束，三项有技术对策
- **执行顺序建议**：今天 Stage 0（0a/0b/0c）→ 按决策规则定 GO → 今晚-明天 Stage 1-2
